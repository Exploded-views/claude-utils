# Changelog (fork)

Changes this fork makes to upstream `claude-utils`, newest first. Each entry is
marked **fork-only** (tied to this fork's layered `mem-*` model) or **upstream
candidate** (useful on its own; not proposed upstream yet). Versions before the
fork are upstream's own releases.

## Unreleased

- **`identity backup`**: `claude-memsync identity backup --store-cmd "<argv>" [--verify-cmd "<argv>"] [--identity <path> | --all | --repo <name> | --config <path>] [--dry-run]` stores each age identity file this host needs (its clones', the defaults related clones read with, and the classic files `rekey-pq` keeps) through your password manager (the key on the command's stdin only, never printed, logged or put in an argument or the environment), reads it back with `--verify-cmd` and compares SHA-256 digests, and refuses a file that is not mode 0600, yours, a single hard link, a regular file (not a symlink) and an age identity (#3). With several identities the title must carry `{fingerprint}` or `{name}`, or it exits 2; it ends with an `N stored (M verified, K UNVERIFIED), F failed` line, and turns core dumps off. Also `claude-memsync version --json` (and `claude-memmerge version --json`): one JSON line with `name`, `version`, `commit`, `go`, `os`, `arch`; the plain `version` text line is unchanged, any other argument exits 2, and both are documented as stable. *Upstream candidate.*
- internal/sync coverage no longer depends on timing (#6)
- **Integration review fixes**: hooks (`changes --hook`, `related context`) and the doctor timer (`doctor --unattended`) never run a token or key command or reach the network (cached related-repo visibility verdicts only; the GitHub client is built only when a verdict is needed); interactive mutators refuse a repo with an unfinished `rekey-pq` before stopping the service, `join accept|reject` stop on a divergence from origin, `retire-classic` keeps the classic identity while a related read clone still lists it, the auto restart checks the service really runs, `recipients label --all` stops it once, `join status` shows the `.gitattributes` notice, and one release-version rule (`v0.3.0-ev.1` included) covers `package-release.sh`, `bootstrap.sh` and `release.yml`, which now builds with CI's Go. *Fork-only.* After upgrading, re-run `claude-memsync doctor --install-timer` so the timer passes `--unattended`. A cached "not private" verdict now hides a related repo whatever the token setup, `relatedMaxStaleHours` is capped at 24, `label --all` and `host retire --apply` respect the rekey guard, and `retire-classic` keeps the identity when the related clones cannot be checked.
- **One config dir, and a CI cache fix**: routes.json, apps.json and the age identity all live in `$XDG_CONFIG_HOME/claude-memsync`, else `~/.config/claude-memsync`, on every OS (the identity used the OS config dir: `~/Library/Application Support` on macOS, `%AppData%` on Windows). An identity still in the old place stays there and keeps being used (each clone's git config holds its absolute path, so do not move it; a safe `identity move` is planned), `status` says so once, and nothing is moved or duplicated. `scripts/bootstrap.sh` follows the same rule, including `XDG_CONFIG_HOME`. Test builds of the binary keep the caller's Go module and build caches, so `t.TempDir` cleanup no longer fails on read-only module files in CI. *Upstream candidate.*
- **mac setup UX fixes**: key and token commands wait 120 s at a terminal (`CLAUDE_MEMSYNC_SECRET_TIMEOUT` to change it; the daemon keeps 10 s) and say they are waiting for the password manager; `recipients` writes, `join request|accept|reject` and `distill --prune` stop a running service for the change and always start it again (never one that was not running); `--repo` accepts the GitHub repo name or `owner/name`; `join status|list` show each key's label and `join accept` prints the accepting host's own key; a changed `.gitattributes` is explained instead of shown as an unpinned key. *Upstream candidate.*
- **rekey-pq recovery fixes**: a rerun after the daemon synced reports "already done" instead of failing verification (also for restore records written by the previous build, whose migrated commit is inferred from the history), and `recipients retire-classic` retires the classic identity on its own; `--rollback` refuses to drop commits made after the rekey (`--discard-local-commits`) and needs the classic identity (renamed back from `.classic-retired`); retirement honours other clones' unfinished restore records; every resume repoints and resets the index; the daemon will not sync a repo with an unfinished rekey; `--apply` refuses while a park or pull is unfinished; `--drop-backup` refuses an unpublished rekey; the restore record is fsynced and a corrupt one gets recovery advice. *Fork-only.*
- **Bootstrap on a Mac**: a standalone `claude-memsync` or `claude-memmerge` in `~/.local/bin` is moved aside to `<name>.pre-bootstrap-<UTC time>` (never over an earlier backup) before bootstrap links its own build; a re-run adds new keep-out terms to an existing denylist; the plan suggests `KEEP_OUT_OWNERS` when orgs are reachable and none is kept out; the summary says to run `/reload-plugins`; the paste prompts say to keep the password manager unlocked and in view. `--dry-run` keeps an org token file. *Fork-only.*
- **Hook self-deadline**: `claude-memsync changes --hook` gives up after 1.5 s (`--deadline`, `CLAUDE_MEMSYNC_HOOK_DEADLINE_MS`): it then prints nothing, moves no marker, says so on stderr and exits 0, instead of overrunning Claude Code's 10 s timeout and losing the notices. *Upstream candidate.*
- **Bootstrap for homelab and crewkit hosts**: up-front prerequisite checks, exit 3 when the check key is missing, `--delete-org-token-file`, `--prebuilt-dir`, `--keep-out-owner`/`--keep-out-term` (old `--deny-*` names still work), release archives that carry `scripts/bootstrap.sh`, and `release-layout` and `workflow-lint` CI jobs; see `docs/bootstrap.md` and `docs/ci.md`. Mac fix included: the recovery-key check used a regex repeat count of 1000, which macOS's `grep` and bash `[[ =~ ]]` refuse above 255, so every valid post-quantum key was rejected on a Mac; it is now plain parameter expansion (`valid_pq_recipient`, bash 3.2 safe), and `scripts/lint-portability.sh` keeps GNU-only tools out. *Fork-only.*
- **Fork CI and coverage ratchet**: a fork-only workflow (vet, gofmt, race tests, shellcheck, bootstrap harness, gitleaks, reference check) and per-package coverage floors that only rise (`make ratchet`); see `docs/ci.md`. *Fork-only.*
- **Post-quantum encryption by default**: new repos use `encryptionScheme: pq` (hybrid ML-KEM-768 + X25519, `age1pq1…`); classic X25519 only on request; `recipients rekey-pq` converts a single-member classic repo, optionally onto one fresh root commit. *Upstream candidate.*
- **PQ follow-ups**: related reads find `identity-pq.<ext>` (and no longer need `identity.txt`) after `rekey-pq`; `bootstrap.sh` has no built-in allowed orgs or own owners (allowed orgs are `--org` plus `--allow-org`; own owners are `--org` plus `--own-owner`, so pass `--own-owner <github-user>` for a personal account); `rekey-pq --all` without `--apply` ends with `dry run: N ok, M would fail` and exits nonzero if any would fail. *Upstream candidate.*
- **rekey-pq hardening**: `--all` stops at the first failure and reports done/failed/not started; a rerun resumes, `--rollback` undoes an unpushed migration; checks run before any local change and `config.json` is saved only after the push; the classic identity is kept while any clone under the sync root uses it; synced-head follows the rekey; also `SchemeOf` falls back to the recipients file, `-h` never acts for `start`/`stop`/`status`/`uninstall`/`version`, `app add --verify` checks before writing, `init` refuses `--github-app` with `--token-cmd` and reuses `identity-pq.txt`. *Upstream candidate.*
- **Explicit token flags win**: `--token-file`, `--token-cmd` and `--github-app` replace every configured token source for `doctor`, `host` and `repo create`. *Upstream candidate.*
- **Safer app registration**: `app register` refuses unreplaced `<…>` placeholders, keeps the key in a `recovered.pem` if storing it fails, and `app add --replace --verify` repairs an entry. *Upstream candidate.*
- **Filters follow the binary**: after an upgrade the daemon repoints each clone's age filter and merge drivers at the running binary. *Upstream candidate.*
- **User guide**: `docs/setup.md`, `docs/security.md`, generated `docs/reference.md` with a CI staleness check, this changelog. *Fork-only.*
- **Docs for the first release**: `docs/fork.md` (the fork's model overview, moved out of the shared README, which keeps only a "This fork" pointer, plus the known follow-ups), `docs/releases.md` (verify, extract and install a release archive), macOS notes and a config-directory section in `docs/setup.md`, the planned performance budgets in `docs/ci.md`; stale statements about the Go version, the version a plain `go build` reports and the per-recipient size corrected. *Fork-only.*
- **Help text**: two flag descriptions (`init --recovery-recipient`, `join --allow-unlabelled`) used backticks, which Go's flag package rendered as the flag's value name in `-h`; they now use plain quotes. *Fork-only.*
- **Host bootstrap**: `scripts/bootstrap.sh` sets up a host in one pass (roles, repos, deploy keys, routes, init, join requests, per-host check key) with a dry run first, and a one-prompt paste for new hosts. *Fork-only.*
- **Host lifecycle**: host labels on deploy keys and recipients, `host list` (stale/expired), `host retire` (dry run, `--apply`), `host check-key`, read-only members, `--expires`. *Fork-only.*
- **Related-project suggestions**: `related suggest|accept|dismiss` offer read relations from this host's own session data, within the client boundary. *Fork-only.*
- **GitHub App auth**: `app register` (manifest flow, key to a file or a password manager), `app-token`, `app key-fingerprint`, `githubApp` in config; short-lived installation tokens instead of long-lived PATs. *Upstream candidate.*
- **Join requests and token commands**: `join request|status|list|accept|reject` with a fingerprint a person compares; `--token-cmd` / `githubTokenCmd` read the GitHub token from a command, never saved. *Upstream candidate.*
- **Foreign-writer guard**: the daemon holds while another sync tool may still write into the Claude folders (`foreignWriters`), plus a start-up quiet window. *Upstream candidate.*
- **Home-folder routing**: `route home|publish|inherit`; the home folder pins per host (including to the personal repo), templates shared through the registry with client rules turned into denies. *Fork-only.*
- **age encryption at rest**: clean/smudge filter, decrypting merge driver, pinned and reviewed recipient sets, plaintext push guard, `recipients add|remove|list|accept|label`. *Upstream candidate.*
- **Related projects**: `relate`, `unrelate`, `related [sync|context]`: read-only, never-mirrored copies of related repos and a SessionStart index, with default-deny boundaries. *Fork-only.*
- **Archive, never delete**: `--archive-deletes` moves deleted notes to `archive/<date>/`; `archive list|search`; `distill --prune` archives. *Upstream candidate.*
- **Renamed remotes**: `aliases` on remote rules and a root-commit fallback with a grace period keep routing a renamed or transferred repo. *Upstream candidate.*
- **Several repos per host**: `routes.json` with repo kinds, first-match folder/path/remote rules, default deny, one loop per repo. *Upstream candidate.*
- **Private repos only + doctor**: `mem-*` name allowlist, `repo create` verified private, hourly re-check, `doctor` (and a daily timer), trusted-config rules. *Fork-only.*
- **Pinned releases**: tag-triggered release workflow with `SHA256SUMS`; published assets are never overwritten. *Upstream candidate.*
- **Changes since a commit**: `changes` (and `changes --hook` for Claude Code) list the memory files changed since a marker, so a running session hears about them. *Upstream candidate.*
- **Secret scrub and denylist**: held-back commits for files that look like credentials or match a denylist, with parking around pulls and recovery. *Upstream candidate.*
